Drive and inspect iOS apps on a booted Simulator, or read-only inspect a physical device, on a macOS host (local, or a remote Mac via 'ssh_host').

axe describe-ui is the sensor: every interaction resolves a selector against the live accessibility tree before acting. Screenshots are for visual judgment, never for computing tap coordinates. The tree reports POINTS, screenshots PIXELS -- ui_dump always returns both, labeled ('frame_points'/'frame_pixels', 'center_points'/'center_pixels'), plus the measured 'scale'. Never trust a bare coordinate whose unit is ambiguous.

Environment:
- doctor: host readiness -- macOS, DEVELOPER_DIR/Xcode, simctl, axe, pymobiledevice3, runtimes, booted simulators, physical devices, per-device Developer Mode + passcode blockers, DDI availability vs each device's iOS version. Every check runs even after an earlier one fails; it never errors, always returning a report
- list_targets: simulators + physical devices in one list; ambiguous (>1 ready target, no explicit 'udid') is an error

Simulator lifecycle -- create_sim, boot, shutdown, install, launch, terminate:
- create_sim: 'name' required, 'device_type'/'runtime' OPTIONAL -- see their parameter descriptions for the friendly-name/identifier contract
- boot/create_sim/install/launch/screenshot/ui_dump each take their own larger budget from tool config -- 'boot_timeout_s', 'create_sim_timeout_s', 'install_timeout_s', 'launch_timeout_s', 'ui_dump_timeout_s', 'screenshot_timeout_s', falling back to 'command_timeout_s' (120s) -- sized for real ssh_host and first-run CoreSimulator latency. A timeout ALWAYS raises a distinct error naming the command and the budget it exceeded, never an empty/absent result
- CoreSimulator's benign 'Install Started'/'Install Failed: Authorization is required to install the packages.' noise (OPTIONAL components denied, not the command failing) never turns a success into an error; it surfaces in 'warnings'

Simulator sensing:
- screenshot: writes a PNG to disk (path, never inline) via the runner's local/ssh-transparent transfer
- ui_dump: parsed accessibility tree (type, role, label, value, unique_id, enabled, frame_points+frame_pixels, center_points+center_pixels, scale) -- not raw JSON
- find: nodes matching a selector, centers resolved in both units
- logs: bounded `simctl spawn log stream` capture -- see 'duration_s'

Simulator interacting, selector-first. INFERRED = an axe argv shape not independently verified, and those ops always warn; VERIFIED = proven.
- tap: dump -> resolve selector -> tap via axe's VERIFIED '--label' resolution (the node's own label) -> re-dump -> report. Refuses a resolved node with no label rather than guess a coordinate. Returns 'tapped_at_points'/'tapped_at_pixels' -- what axe's own tap confirmation reported, never a bare guess -- and 'before' (the node's label/type/frame_points/frame_pixels: WHAT was tapped, not just where). A null coordinate is never silent: 'tap_point_note' says why (confirmation unparsed, vs. parsed but pixel scale unavailable). 'total_node_count_before'/'total_node_count_after' count ui_dump's 'total_node_count' population (every node), not its labelled/valued-only 'node_count'
- tap_xy: RAW point coordinates via an INFERRED axe coordinate-tap flag
- type_text: tap to focus -> INFERRED 'axe type' -> re-dump. Cannot assert focus was gained (the iOS accessibility JSON here carries no 'focused' attribute). Reports the tap-to-focus step's 'tapped_at_points'/'tapped_at_pixels'/'tap_point_note' exactly as 'tap' does, plus an explicit 'value_after_note' (never a silent null) when the selector could no longer be re-resolved after typing to read back 'value_after'
- key, swipe: INFERRED axe argv shapes
- wait_for: polls ui_dump until a selector appears/disappears, or timeout -- no bare sleeps

Device tier (read-only sensing; free, no Apple Developer account):
- device_info: ProductVersion/ProductType/DeviceName/CPUArchitecture + DeveloperModeStatus, asked of the DEVICE (pymobiledevice3-preferred over a local-only check -- the design doc's 'tool error vs device error')
- device_screenshot: requires the Developer Disk Image mounted first (see device_mount_ddi)
- device_apps: INFERRED pymobiledevice3 'apps list'
- device_elements: VERIFIED pymobiledevice3 accessibility list-items -- NO GEOMETRY (caption/estimated_uid/platform_identifier/spoken_description only)
- device_enable_devmode: when a set passcode blocks it (undocumented Apple behaviour), the error carries the temporary-disable-then-restore guidance in the SAME message, never a bare 'turn off your passcode'
- device_mount_ddi: picks the nearest DDI at or below the device's iOS version -- never the newest Xcode-shipped one by assumption; newer Xcode may ship none for this device at all

tap/tap_xy on backend='device' ALWAYS refuse -- see device_elements' 'no geometry' above.

Selector: {"label": "General"} | {"label_contains": "Gener"} | {"value": "On"} | {"role": "..."} | {"type": "..."} | {"unique_id": "..."}, optional "index" to disambiguate. Multiple keys AND together. An ambiguous match (>1 node, no index) is an error listing candidates.
